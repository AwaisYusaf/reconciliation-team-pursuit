| D-30 | 2026-08-16 | **Uploads are proxied through the server, not presigned direct to storage.** Every upload must be inspected and normalised server-side anyway (R4.6), and presigning would move bytes client→storage→server→storage; proxying moves them client→server→storage. One request instead of two, no window in which an orphaned draft object exists, and identical behaviour on both storage drivers. Supersedes the presign+attach contract in data-model §S3; the client still never sees or sends object keys. | Fewer transfers, no orphan cleanup, dev/prod parity |
| D-31 | 2026-08-16 | **Generators are pure `(snapshot) => bytes`; one `loadMonthSnapshot` feeds all three.** The database is read once per download and the cover sheet, workbook and packet all describe the same instant, so R10.2 holds by construction rather than by discipline. Generators are unit-testable against fixtures with no database. | Agreement between outputs must be structural, not a rule someone remembers |
| D-32 | 2026-08-16 | **Output cache keyed by a canonical-JSON hash of the snapshot plus a per-generator version string.** Key order is sorted so a query returning columns differently cannot invalidate the cache; the version string means a layout change rebuilds without anyone clearing anything. Serving a download always pins the artifact (D-21/R10.6), so the partial unique index constrains only unpinned rows and concurrent downloads cannot collide. | R10.4 needs a hash that changes exactly when the bytes would |
| D-33 | 2026-08-16 | **Download buttons fetch and hand over a blob rather than being plain links.** A refusal by the documentation gate is a normal, expected outcome, and a link would replace the app with a page of plain text; fetching keeps the user in place and turns the refusal into a toast listing what is missing. The gate is still enforced server-side — the button state is only a courtesy. | R4.3 refusals are routine, not errors |
| D-34 | 2026-08-16 | **Percentages normalise binary representation error before applying R1.5.** An exact 57.5% arrives as 57.49999999999999 and rounded down to 57, while Excel — which normalises to 15 significant digits before rounding for display — showed 58 in the same cell. `percentValue` now normalises the same way, and the workbook writes the already-rounded value so only one renderer rounds at all. | R1.5 must apply to the value the user means, and R10.2 forbids the screen and the file disagreeing |
| D-35 | 2026-08-16 | **The month snapshot is read in one repeatable-read, read-only transaction, and the active month's amounts are derived from the expense rows rather than queried separately.** As independent statements, an expense created mid-read could reach the figures without reaching the set the documentation gate inspects — a gate bypass producing a workbook whose sheets disagree. | R4.3 is the product's core promise; it must not depend on statement timing |
| D-36 | 2026-08-17 | **`convertDocxToPdf` refuses input that is not a zip.** LibreOffice sniffs content rather than trusting the extension and silently treats unrecognised input as plain text — a malformed document converts into a perfectly valid PDF of garbage and exits 0. Checking the `PK` magic bytes, and checking that a `.pdf` was actually produced, turns a silent wrong document into an error before anything reaches the City. | Found by testing the real converter rather than a mock |
| D-37 | 2026-08-17 | **Values shared between a page and its client component live in a neutral module, never exported from the `"use client"` file.** A non-component value imported from a client module into a Server Component arrives as a client-reference proxy rather than the value, so an equality check against it silently fails at runtime with no type error — "All Line Items" rendered a single sheet. | Next-specific footgun, found in browser testing; typecheck and lint both passed |
| D-38 | 2026-08-17 | **All text drawn with a pdf-lib standard font passes through `winAnsiSafe` first.** Standard fonts encode WinAnsi only and pdf-lib *throws* outside it, so one invisible pasted character — a non-breaking hyphen, a zero-width space — in an organisation or line item name aborted every packet build permanently. Names are user data and cannot be restricted to Latin-1, so text is folded to the closest representable form instead. | A document with an imperfect character beats no document at all |
| D-39 | 2026-08-17 | **Rasterization verifies its own output.** `pdftoppm` exits 0 while rendering only some pages, and answers absurd page geometry with a 1×1 pixel image. Page count is checked against what was recorded at attach time, and degenerate renders are rejected. | A blank page where a receipt should be is the worst failure this system has, and it was silent |
| D-40 | 2026-08-17 | **Guards that detect misfiled evidence fail closed.** The org-prefix checks in the packet and cover sheet paths now throw rather than returning early; a short image array is asserted rather than tolerated. | Silently omitting a document from a reimbursement claim is worse than failing loudly |
| D-41 | 2026-08-17 | **Removed the storage driver's signed-URL method and its HMAC helpers.** D-30 replaced presigned access with server-proxied downloads, so nothing called it — and the local implementation returned `/api/files/local`, a route that does not exist. Its docstring claimed a security property that was never in play. `/api/files/[id]` authenticates the session and scopes the lookup to the organisation, which is strictly stronger than a bearer URL. The `@aws-sdk/s3-request-presigner` dependency went with it. | Dead code that claims a security guarantee is worse than no code |
| D-42 | 2026-08-17 | **A recurring item's row matches by name for display but only removes what it created.** R8.3's display rule is name plus line item, which usefully warns that the month already holds such a record whoever entered it. Removal is stricter: an expense the item did not create is always confirmed first, even with no documents, and the wording says it was not added from here. The screen previously omitted the item's id entirely, so it and its own actions disagreed — one path duplicated a salary line, the other deleted a hand-entered expense. | Display and deletion do not warrant the same level of certainty |
| D-43 | 2026-08-17 | **A retired label stays selectable on the record that already carries it.** Validation only requires a currently-active label when the value changes. Otherwise deactivating a payment source made every historical expense uneditable, and the only way to save was to overwrite a snapshot that had already printed on a submitted cover sheet (R5.1, R5.2). | History is not rewritten by a settings change |
| D-44 | 2026-08-17 | **Production refuses to start without `TRUSTED_PROXY_HOPS`.** Without it the client address cannot be identified, both login limiters collapse into global buckets, and an attacker's wrong guesses lock out the real user — the exact denial of service the no-lockout design exists to avoid. Mirrors D-29's refusal to run on the local storage driver in production. | A silent security degradation is worse than a startup failure |
| D-45 | 2026-08-17 | **Pinned artifacts survive their line item** (`ON DELETE SET NULL` rather than cascade). Deleting a line item must not erase the evidence that a cover sheet for it was submitted (R10.6, D-21). | The submission record outlives the budget structure |
| D-46 | 2026-08-17 | **Session tokens are stored as an HMAC keyed by `AUTH_SECRET`, not a bare SHA-256.** The variable had been documented as protecting sessions while nothing read it — an operator rotating it after a suspected compromise would have believed every session was dead when none were. Rotation now genuinely revokes everything, which with one shared account, no self-serve reset (D-24) and no session-list UI is the only such lever that exists. | A documented security control that does nothing is worse than none |
| D-47 | 2026-08-17 | **Sessions have a 90-day absolute cap on top of the 30-day sliding window.** Renewal alone has no end: a stolen cookie touched once a month stays valid forever, and the staff have no UI that would reveal it. | The sliding window needs a floor under it |
| D-48 | 2026-08-17 | **Rate-limit keys are truncated and buckets swept lazily inside `consume`.** Keys are built from caller-supplied values, so an unauthenticated request could pin unbounded memory — measured at 772 MB from 900 buckets, at a request rate the per-IP limit itself allows. Sweeping on demand rather than on a timer means nothing has to be started at boot and behaviour does not differ between a warm and a cold process. | An OOM of the single container is the denial of service the no-lockout design exists to prevent |
| D-49 | 2026-08-17 | **`instrumentation.ts` refuses to start production without its required settings.** Several were checked at first use instead, so a misconfigured deploy booted, served the login page, and failed with an error boundary the moment anyone signed in — while the documentation claimed it would refuse to start. | Make the claim true rather than softening it |
| D-50 | 2026-08-18 | **The database handle connects on first use, not on import.** `next build` collects page data by importing every route module with none of the runtime environment present, so building the image failed on `/login` with "DATABASE_URL is not set" — for a page that queries nothing. Exported as a proxy rather than a `getDb()` function so all 42 call sites keep reading `db.select(…)`. | Nothing is lost: `pg.Pool` opens no socket until the first query either way, and a missing URL is still caught at startup by D-49 |
| D-51 | 2026-08-18 | **The image installs the npm version named in `package.json`'s `packageManager`, and passes `--include=dev` to `npm ci`.** npm 10 (bundled with node:22) and npm 11 resolve transitive optional dependencies differently, so a lockfile written by 11 fails `npm ci` under 10. Separately, `ENV NODE_ENV=production` makes npm omit devDependencies — 189 packages instead of 568 — dropping `@tailwindcss/postcss`, `drizzle-kit` and `tsx`. | Both failures surface only in the production build, which is the worst place to find them |
| D-52 | 2026-08-20 | **Every `w:line` the cover sheet emits states its `w:lineRule`.** OOXML treats a missing rule as `auto`, but LibreOffice 7.4 — the build the container ships — reads it as an exact 240-twip line and clips inline images to it, collapsing every proof to a 0.167in band and the whole sheet to one page. The generated bytes were always correct; only that renderer disagreed. | The bug is invisible on a developer machine, whose newer LibreOffice renders the same file correctly — so the guard is an assertion on the emitted XML, not on a rendered page |
| D-53 | 2026-08-20 | **A clicked vendor overwrites; a typed one only fills blanks — and a typed amount is never overwritten.** Filling blanks only made clicking a suggestion appear to do nothing once a line item had been chosen, which was the whole complaint. Typing stays conservative because it fires from characters the user was entering anyway. The subtotal is exempt from the overwrite because it is offered as a starting point and is new on every expense. | Two different gestures, two different intents; the rules live in `vendor-fill.ts` so they are testable rather than buried in the form |
| D-54 | 2026-08-20 | **Remembered vendor amounts are nullable, not defaulted to zero.** `null` means nothing has been learned; `0` means this vendor genuinely charges no tax, which is the common case. Collapsing them would prefill every new expense with a confident $0.00 the library never learned, and clearing an amount in Settings would be impossible to express. | The whole value of the feature is that what it offers was actually observed |
| D-55 | 2026-08-20 | **A remembered payment source is withheld once its label is retired.** Stored as the label rather than a foreign key, matching `expenses.payment_source`. R5.2 keeps a retired label readable on the records that already carry it, so autofilling one onto a *new* expense would reintroduce it by the back door. `vendor-fill` takes the active list and contributes nothing when the remembered label is not in it — and defaults that list to empty, so a caller that forgets to pass it fills nothing rather than resurrecting a retired label. | The one way a convenience feature could quietly violate a domain rule |
| D-56 | 2026-08-20 | **The nightly dump is a pipe between the two containers, and never touches the host disk.** `pg_dump` runs in the postgres container so its version always matches the server; the app container uploads, because that is where the S3 credentials already are. Neither needs a package it does not ship, and a backup cannot fill the volume the database runs on. | The usual ways a backup regime rots: a client/server version skew after an upgrade, and a dump directory quietly consuming the disk it is protecting |
| D-57 | 2026-08-20 | **Retention is the bucket's lifecycle rules; the backup job only ever writes.** 30 daily and 13 months of monthlies, with noncurrent-version rules because the bucket is versioned. The uploader also reads each object back and compares its length before reporting success. | A backup job with delete permission can delete the wrong thing unattended; and an upload that reports success while storing nothing readable is the exact failure the regime exists to prevent |
| D-58 | 2026-08-20 | **Cover sheet body text is 10 pt, matching the approved documents' text rather than their default.** The spec had specified 11 pt as "the golden docs' theme default", which is true of their `docDefaults` and true of no text in them — every run overrides to 10 pt. Typography is not among the recorded standardizations, so "we match their look" governs. `page-estimate.ts` moves with it, since its line height and characters-per-line were derived at 11 pt. | The City approved a document at 10 pt; shipping 11 pt made every sheet visibly taller than the one they signed off |
| D-07 | 2026-08-16 | **Postgres self-hosted with Drizzle ORM** — Docker container + volume on Mantaq infra (local Postgres in dev); drizzle-kit migrations; schema authored in `src/db/schema.ts`. Backup regime unchanged and non-negotiable: nightly pg_dump → S3 (30 daily + 12 monthly), bucket versioning, one executed restore drill, host disk encryption. | User stack decision (Drizzle over Prisma) |
